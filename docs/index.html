Running after a clone

There is no curl-to-a-random-domain installer. Clone the public repo, run ./install.sh, pull a local model, then talk in Telegram.

01

Clone the repo

Source of truth is GitHub. You build on your Mac with the Swift toolchain you already trust.

$ git clone https://github.com/ValDagon/slam.git
02

Install the service

Release binary to ~/.local/bin, LaunchAgent plist, bootstrap gui/$(id -u). Prompts for a BotFather token if Keychain is empty.

$ ./install.sh
03

Pull a local model

Default in docs is qwen2.5:7b. Inference is on your machine; the daemon does not ship weights.

$ ollama pull qwen2.5:7b
04

Talk in Telegram

Zero GUI. /status reports RSS, CPU, DB, and sandbox. Chat is a model turn; destructive shell waits for a button.

$ /status

Shell access you can contain

The analog of a “receipt” here is the Seatbelt profile the child actually runs under — deny-default, write-scoped, no network, secrets not in files.

Supervised commands

Destructive patterns from config wait on Telegram inline buttons (10-minute timeout, then deny).

OS sandbox

sandbox-exec Seatbelt, not Docker Desktop. Boot smoke (FR-24): if the profile fails, the run channel stays off and the daemon stays up.

Workspace policy

Read: system paths needed to exec plus the workspace. Write: WORKING_DIR/tmp. Sensitive trees are explicitly denied.

Keychain, not files

Bot token is kSecClassGenericPassword (service com.local.slam). It must not appear in git, plist, logs, or issues.

Built around macOS

Killer features are constraints, not a pitch deck: Swift 6, launchd, Keychain, Seatbelt, QoS, idle budget, keep_alive: 0.

Fully Swift 6

SPM executable, language mode Swift 6, -strict-concurrency=complete. Shared mutable state lives in actors or is Sendable.

LaunchAgent lifecycle

KeepAlive, RunAtLoad, ProcessType=Background. launchd owns the process; you do not leave a forever-run in Terminal.

Keychain secrets

The Telegram token is not in .env. config.json holds non-secrets only (allowlist, model, paths).

Seatbelt isolation

Model-issued shell is Foundation.Process + sandbox-exec. Native Ollama tools write_file / run_shell, with a fence fallback.

E-core idle

QoS .utility / .background for waiting work. Spec: RAM ≤ 100 MB idle, CPU ≲ 1% between long-polls.

VRAM hygiene

Ollama keep_alive: 0 on every request, plus an idle unloader, so laptop GPU memory is released after each answer.

What you can do today

Alpha: a personal Telegram daemon on one Mac. Not a multi-channel platform. Honest scope beats a fake catalog.

Personal assistant

Chat from Telegram. Memory is SQLite (GRDB, WAL, FTS5) on disk, not a rented cloud notebook.

Sandboxed shell

Ask for disk usage or a workspace listing. The child has no network; writes outside tmp are denied.

Files in tmp

write_file and redirects may land only in WORKING_DIR/tmp in this release. That limit will widen.

HITL confirmations

rm-class patterns do not run until you tap the inline button. stdout/stderr come back into the chat.

Health in chat

/status reports uptime, RSS, CPU, database, and sandbox. Logs stay under ~/.local/state/slam/logs/.

Local model

Default docs model is qwen2.5:7b via localhost Ollama. Other local names work through /model.

Fair vs ZeroClaw

ZeroClaw is a strong Rust agent with many channels. This project does not try to replace that. Native Swift/macOS-first is the point.

Questions, answered

S.L.A.M (Swift Light Agent for Mac) is a native headless AI agent for macOS (Apple Silicon): a Swift 6 daemon you talk to over Telegram, with local Ollama for inference and sandbox-exec for model-issued commands. Zero GUI — launchd owns the process.
Yes. MIT license. No subscription and no hosted seat. You pay only for hardware and whatever local model you run.
Spec idle budget is RAM ≤ 100 MB and CPU ≲ 1%. Measured idle RSS on the development Mac was around 18 MB. 121 tests / 22 suites gate the public snapshot.
The daemon and Ollama run locally. Telegram is the control channel, so messages you send go to Telegram’s API — that is inherent to a Telegram bot. There is no S.L.A.M cloud in the middle. The bot token never sits in a file.
Token in Keychain. Allowlist of Telegram user IDs. Seatbelt deny-default with tmp-only writes in alpha. Destructive commands need a human button. sandbox-exec is probed at boot.
Telegram only in this release. Local Ollama on localhost. Extra networks (Discord, Slack, iMessage, …) are explicit non-goals for v1.
